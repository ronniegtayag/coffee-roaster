## 2. MYOB products (what "MYOB" can mean)

| Product                                              | What it is                                                                         | API                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **MYOB Business** (browser; plans such as Lite/Pro)  | Current small-business product. Former "Essentials" users have been moved onto it. | **MYOB Business API** (the former AccountRight API). Per MYOB's docs it works with both online and desktop company files. **[Confirmed]** ([auth docs](https://developer.myob.com/api/myob-business-api/api-overview/authentication/)). The Essentials migration is **[Assumption — confirm with roaster]** (we just need to know what they log into). |
| **AccountRight** (desktop, optionally "online" file) | The older Windows product. The file can live on the PC or in MYOB's cloud.         | Same API. An **online** file uses OAuth via my.MYOB. A **desktop** file is reached on the local network with the file's username and password, so it does not suit a cloud-hosted app. **[Confirmed]** ([auth docs](https://developer.myob.com/api/myob-business-api/api-overview/authentication/))                                                    |
| **MYOB Advanced** (Acumatica)                        | Mid-market ERP. Unlikely for a small roaster.                                      | A different API and partner program. **[Assumption — confirm with roaster]** that it does not apply.                                                                                                                                                                                                                                                   |
| **MYOB EXO**                                         | Older mid-market ERP.                                                              | API is limited to existing EXO partners. **[Confirmed]** ([developer program](https://developer.myob.com/what-is-the-developer-program/))                                                                                                                                                                                                              |

## 3. What the MYOB Business API can do for us

| Need                              | Possible?                                                                                                                                                                                               | Label                                                                                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create an item invoice in MYOB    | Yes. `Sale/Invoice/Item` supports POST, GET, PUT and DELETE. Each line carries a MYOB tax code, and the invoice can carry the customer's PO number.                                                     | **[Confirmed]** ([Sale/Invoice/Item](https://developer.myob.com/api/myob-business-api/v2/sale/invoice/invoice_item/))                                                                                |
| Read back whether it's paid       | Yes. The invoice has `Status` (Open / Closed / Credit), `BalanceDueAmount` and `LastPaymentDate`. Polling these is enough for "paid / overdue" in our app.                                              | **[Confirmed]** (same page)                                                                                                                                                                          |
| Lines must reference MYOB records | Lines point to existing MYOB items/accounts and tax codes by ID. Customers (MYOB "card files"), items and tax codes must be matched or created first.                                                   | **[Common practice]** ([Apideck guide](https://www.apideck.com/blog/how-to-integrate-with-the-myob-api))                                                                                             |
| Tax codes                         | Australian MYOB files normally use codes such as `GST` and `FRE` (GST-free). Our `GST` / `GST_FREE` must map to the codes in _this_ file.                                                               | **[Common practice]**. The mapping is **[Assumption — confirm with accountant]** (A1).                                                                                                               |
| Auth                              | OAuth 2.0. The app is registered to get an API key and secret. A user of the company file approves access once, and we store a refresh token. Every call sends the API key and `x-myobapi-version: v2`. | **[Confirmed]** ([auth docs](https://developer.myob.com/api/myob-business-api/api-overview/authentication/))                                                                                         |
| Who approves                      | Reported since March 2026: only an **Admin** user of the company file can approve, and the approval covers the chosen company file only.                                                                | **[Common practice]** (third-party help article: [Datawise](https://datawiseltd.freshdesk.com/support/solutions/articles/51000513871-new-myob-authorisation-steps-march-2026)). Check the MYOB docs. |
| Rate limits                       | Reported as 8 requests/second and 1,000,000/day per key, with at most 2 active keys per developer account. This is plenty for one roaster.                                                              | **[Common practice]** (third-party: [Apideck/DEV](https://dev.to/apideck/how-to-integrate-with-the-myob-api-3gf5)). Check the MYOB docs.                                                             |

## 4. Cost and approval hurdles

- **Developer Program** tiers (AUD incl. GST per month): Developer Access $110, Developer Partner $220, Premium Developer Partner $630. **[Confirmed]** as listed on [MYOB: What options do I have?](https://developer.myob.com/what-is-the-developer-program/). The page does **not** say whether paid membership is needed just to get an API key for one business's own integration. Other sources disagree on prices. **[Assumption — confirm with MYOB]** before budgeting.
- MYOB may accept or decline Developer Partner applicants at its discretion, and members must meet MYOB's developer security requirements. **[Confirmed]** ([Developer Program T&Cs](https://developer.myob.com/program/myob-developer-program-v2)).
- **Alternative:** a unified-API vendor (e.g. Apideck) or an off-the-shelf connector. This adds a monthly fee and a dependency. Only worth it if MYOB's own access is blocked.

## 5. What this changes for the plan

Two options:

| Option                                            | Our app does                                                                                                                                                                                                                                                                                                   | MYOB does                                                                                                                                    |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Recommended: our app prepares, MYOB issues** | Customers, prices, standing orders, delivery. When an order is delivered (or weekly for consolidated accounts), it **creates the invoice in MYOB** and keeps a frozen copy of what was billed plus the MYOB invoice ID. It reads back `Status` / `BalanceDueAmount` to show paid/overdue and flag credit hold. | Invoice numbering, sending invoices (or we send MYOB's PDF), payments, bank reconciliation, credit notes, aged debtors, BAS, supplier bills. |
| **B. Our app issues, MYOB only gets the result**  | Its own tax-invoice numbering, PDFs, payments and credit notes, then pushes totals to MYOB.                                                                                                                                                                                                                    | Ledger only.                                                                                                                                 |

**Why A:** the bookkeeper keeps working in MYOB, there is one invoice-numbering sequence, and we don't rebuild payments, credit notes or BAS (schema-gap G12, G13 shrink to "read back" only). It also matches what operations tools do with accounting software (**[Common practice]**, see `roaster-software-landscape.md`). The trade-off: the MYOB connection becomes a Must before invoicing goes live, and invoice timing depends on MYOB being reachable. **[Assumption — confirm with roaster]** via Q1b and Q1c.

**Fallback if the file is desktop-only or the API cost is rejected:** our app produces a MYOB **import file** (MYOB supports importing sales) for the bookkeeper to load. This needs no API but is manual. **[Assumption — confirm with roaster]**.

Impact on the gap analysis: G22 becomes **Must**. G6 stays **Must** (frozen "what we billed" + MYOB ID). G12 and G13 drop to **Later**, as long as MYOB owns credits and payments. The `Invoice.invoiceNumber` owner is MYOB under option A.
